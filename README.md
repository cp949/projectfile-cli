# @cp949/projectfile-cli

[`@cp949/projectfile`](https://www.npmjs.com/package/@cp949/projectfile) 형식의 프로젝트 파일과 폴더를 서로 변환하는 CLI다.

- 파일 내용을 보지 않는다. 모든 파일을 asset(원본 바이트)으로 담는다. 바이트가 그대로 왕복한다.
- scramble 키는 라이브러리의 기본 키(`DEFAULT_SCRAMBLE_KEY`)만 쓴다.
- Node 24.18 이상에서 동작한다.

## 설치

```sh
npm install -g @cp949/projectfile-cli
# 또는 설치 없이
npx @cp949/projectfile-cli --help
```

## encode

```sh
projectfile encode --kind <kind> [-v1|-v2] -o <출력 파일> <경로...>
```

경로마다 마지막 이름으로 들어간다. `.`만 현재 폴더의 내용을 최상위에 넣는다.

| 명령                                       | 프로젝트 파일 안의 경로     |
| ------------------------------------------ | --------------------------- |
| `projectfile encode ... aaa/`              | `aaa/test.txt`, `aaa/sub/…` |
| `cd aaa; projectfile encode ... .`         | `test.txt`, `sub/…`         |
| `projectfile encode ... aaa/test.txt`      | `test.txt`                  |
| `projectfile encode ... aaa/test.txt bbb/` | `test.txt`, `bbb/…`         |

- 인자 사이에 최상위 이름이 겹치면 실패한다.
- 빈 폴더도 담는다.
- 폴더 안의 이름은 코드 유닛 순으로 담는다. 같은 입력은 같은 바이트가 된다.
- 심볼릭 링크와 일반 파일·폴더가 아닌 항목은 실패한다.
- 출력 파일이 이미 있으면 실패한다.

옵션:

| 옵션     | 내용                                                     |
| -------- | -------------------------------------------------------- |
| `--kind` | 필수. 정규식 `^[a-z0-9][a-z0-9._-]{0,63}$`를 지킨다.     |
| `-v1`    | 포맷 버전 1. 기본값. ZIP 메타데이터와 manifest만 섞는다. |
| `-v2`    | 포맷 버전 2. ZIP 전체를 섞는다.                          |
| `-o`     | 필수. 출력 파일 경로.                                    |

포맷 버전 1은 파일 본문을 섞지 않는다. 모든 파일이 asset이라 압축도 하지 않으므로 본문이 평문으로 남는다. 소스 코드를 담으면 `-v2`를 쓴다.

## decode

```sh
projectfile decode -o <출력 폴더> <파일>
```

- kind는 파일 헤더에서 읽는다. 옵션이 없다.
- 포맷 버전 1과 2를 모두 연다.
- text 항목은 UTF-8 바이트로, asset 항목은 원본 바이트로 쓴다. 다른 앱이 text 항목으로 만든 파일도 연다.
- 출력 폴더가 없으면 만든다.
- 대상 파일이 하나라도 이미 있으면 아무것도 쓰지 않고 실패한다.

## 한도

인코딩과 디코딩이 같은 값을 쓴다. 바꾸는 옵션은 없다.

| 항목                           | 값                       |
| ------------------------------ | ------------------------ |
| 풀린 크기 합계, 파일 하나 크기 | 256 MiB(라이브러리 상한) |
| 경로 길이                      | 1,024(라이브러리 상한)   |
| 파일 수                        | 32,767                   |
| 폴더 수                        | 32,766                   |

- 파일 수와 폴더 수의 합은 라이브러리 규칙상 65,533 이하다. 디코딩은 열기 전에 개수를 모르므로 반씩 나눈 고정값을 쓴다.
- 이름 규칙(빈 조각, `..`, `\`, 제어 문자, 앞뒤 공백, 대소문자 무시 중복 등)은 라이브러리가 검사한다. 어기면 `invalid-name`과 경로를 출력한다.
- Windows 예약 이름(`CON` 등)은 검사하지 않는다. 디코딩은 출력 폴더 밖을 가리키는 경로만 한 번 더 막는다.

| ---- | ------------------------------------------------------------- |

| 2    | 사용법 오류                                                   |
